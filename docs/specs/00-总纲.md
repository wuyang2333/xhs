## 一、产品目标

Spider XHS 从内部单机工具升级为可交付给其他公司的企业系统。

- 我方维护一套主程序、设备工具、官方指令模板和手机适配规则。
- 客户提出需求后，由我方修改、测试并发布更新。
- 程序和官方工具可同步更新，客户业务内容不向我方同步。
- 每家公司可建立自己的员工账号、小红书账号、内容库、图片库、指令库和商品库。
- 每家公司自行配置模型 API，API Key 和费用由客户负责。
- 我方可以监控客户系统版本、在线状态、设备健康、任务成功率和脱敏错误码。
- 我方默认不能查看客户正文、图片、Cookie、API Key 等业务内容。

## 二、目标架构

采用“中央控制面 + 客户本地数据面 + Mac/Windows 设备助手”。

### 1. 我方中央控制平台

负责：

- 客户授权、到期和续费。
- 程序版本和签名更新包。
- 官方工具、官方指令模板和手机适配规则。
- 客户服务端、设备助手和手机的在线健康状态。
- 匿名任务成功率和脱敏错误码。
- 客户授权后的临时远程诊断。

不保存：

- 小红书登录凭证和 Cookie。
- 客户草稿、标题、正文、标签、图片和视频。
- 客户自建指令和商品库。
- 客户模型 API Key。
- 手机 ADB 授权私钥。

### 2. 客户独立 Spider XHS 服务端

每家公司独立部署，负责保存：

- 公司员工、角色和权限。
- 小红书账号及固定手机映射。
- 草稿、发布任务和运营记录。
- 图片、视频、文件夹、产品和场景。
- 客户自建指令和商品库。
- 客户自己的模型配置。

### 3. 设备助手

需要连接手机的 Mac 或 Windows 安装设备助手。普通员工只通过浏览器访问，不需要安装完整程序。

设备助手负责：

- 自动安装和管理 ADB。
- 支持 USB ADB 和无线 ADB。
- 动态发现手机，处理无线 IP/端口变化。
- 开机自启、心跳和版本报告。
- 接收所属公司服务端下发的任务。
- 传图、选图、填写文案、挂车、截图和回传结果。
- 每个操作明确指定目标手机，禁止默认操作“第一台设备”。

## 三、部署方式

### 内部局域网

- 一台主机运行完整 Spider XHS。
- 员工通过局域网 IP 用浏览器访问。
- 连接手机的电脑安装设备助手。
- 普通编辑人员不需要安装。

### 其他公司

每家公司需要一套独立服务端安装包，并按需安装设备助手。

建议交付：

- macOS 企业服务端安装包。
- Windows 企业服务端安装包。
- Docker 企业服务端版本。
- macOS 设备助手 App。
- Windows 设备助手 EXE/MSI。

安装模式：

- 本机单机使用。
- 局域网企业服务端。
- 仅安装设备助手。

## 四、多租户与权限

- 所有业务表引入 tenant_id。
- 后端查询强制按 tenant_id 隔离，不能只靠前端隐藏。
- 数据库、附件、导出、日志和备份均按租户隔离。
- 建议角色：公司管理员、运营主管、内容编辑、发布人员、只读成员。
- API Key、账号绑定、指令修改、最终发布、导出权限分开控制。
- 客户管理员可以建立本公司员工账号和分配权限。

## 五、账号矩阵与多设备

账号矩阵需要显示：

- 所属公司和员工。
- 所属电脑或设备助手。
- 操作系统。
- 手机型号、设备标识和小红书版本。
- 连接方式：USB或无线。
- 当前在线状态和最近心跳。
- 手机校准状态和当前任务。
- 重新配对、检查、校准和切换连接方式。

设计原则：

- 不写死无线 IP、端口和本机 ADB 路径。
- 写死的是“公司 + 小红书账号 + 固定真实手机”的身份映射。
- USB和无线只是可切换的连接通道。
- Windows、Mac mini 和普通 Mac 使用统一设备助手协议。

## 六、图片工坊文件夹

图片工坊的主流程调整为批量上传、外部同步、分类管理、草稿选图和排序。API 生图保留为辅助功能。

需要支持：

- 新建、重命名、移动文件夹。
- 删除空文件夹。
- 文件夹嵌套。
- 批量上传到指定文件夹。
- 批量移动图片。
- 设置文件夹封面。
- 文件夹内拖拽排序。
- 产品、场景、用途、账号和标签筛选。
- 图片搜索、最近上传和最近使用。
- 同一图片可以有一个主文件夹和多个标签。

示例：

- 坐浴盆 / 白底产品图
- 坐浴盆 / 卫生间场景
- 坐浴盆 / 孕期场景
- 坐浴盆 / 使用步骤
- 护腰 / 久坐办公
- 护腰 / 开车

底层建议统一安全存储原文件，由数据库管理文件夹、产品、场景、标签和顺序，不要只依赖物理路径。

## 七、草稿工坊选图与排序

- 草稿工坊底部可以直接选择图片工坊素材。
- 支持按产品、场景、文件夹和标签筛选。
- 支持最近上传、最近使用、一键全选文件夹和防重复选择。
- 已选图片显示序号。
- 支持拖拽排序、设为封面、删除和替换。
- 修改后显示“保存中/已保存”。
- 发送到发布中心前必须等待顺序保存完成。

图片顺序的唯一权威来源是草稿工坊的 sort_order。

顺序链路：

1. 图片工坊选择素材。
2. 草稿工坊拖拽排序。
3. 保存 sort_order。
4. 发布中心按相同顺序复制素材。
5. 传到手机时按相同顺序编号。
6. 小红书按后台顺序点击每张图右上角选择圆圈。
7. 发布前验证任务图片数与手机实际选中数一致。

数量或顺序不一致时必须中止，不能只带一张图片继续发布。

## 八、指令中心复用

指令中心不仅存档，还要成为草稿工坊和图片工坊的统一指令选择器。

### 草稿工坊可选

- 生文、改写、标题、正文和标签指令。
- 合规检查指令。
- 账号、产品和场景专属指令。

### 图片工坊可选

- 生图和图片分析指令。
- 白底图、卖点图、使用场景和风格指令。
- 产品一致性指令。

组合规则：

~~全局基础指令 + 平台指令 + 账号指令 + 产品指令 + 场景指令 + 本次临时补充 = 最终执行指令。~~

要求：

- 执行前展示最终合并的完整指令。
- 支持收藏、最近使用、默认指令和组合模板。
- 支持指令版本。
- 复制后修改不影响原指令。
- 草稿记录实际使用的指令 ID 和版本。
- 官方模板由我方更新；客户模板永不被升级覆盖。

## 九、挂车商品

- 发布中心提供“本次发布需要挂车”勾选项。
- 勾选后使用可搜索的商品筛选框。
- 新商品首次建立后进入客户本地商品库，后续直接选择。
- 商品记录建议包含产品编号、精确名称、显示名称、适用账号和启用状态。
- 手机端流程：添加组件 → 商品 → 搜索 → 精确匹配 → 点击商品左侧圆圈 → 确认添加。
- 找不到商品、存在歧义或无法确认已挂车时必须中止。
- 不允许挂车失败后静默发布普通笔记。
- 发布审核区必须展示最终挂车商品。

## 十、客户自接 API

- 支持文本、视觉理解和图片生成模型。
- 支持服务商模板和 OpenAI 兼容接口。
- Base URL、模型名称和 API Key 由客户管理员配置。
- API Key 仅在客户本地加密保存。
- 普通员工可以使用但不能查看完整 Key。
- 提供连接测试、默认模型、额度限制和脱敏调用日志。

## 十一、更新机制

更新流程：

1. 检查版本。
2. 展示更新内容。
3. 自动备份客户数据库和配置。
4. 下载签名更新包。
5. 校验签名和哈希。
6. 更新程序、官方工具和官方模板。
7. 执行数据库迁移。
8. 重启并健康检查。
9. 上报成功版本。

更新不得覆盖：

- 客户员工和权限。
- 小红书账号、草稿和发布记录。
- 图片、视频、商品库和客户自建指令。
- 客户 API 配置。

更新失败必须能够回滚。

## 十二、发布安全规则

- 最终发布前必须人工确认账号、手机、图片顺序、标题、正文、标签、可见性和商品。
- 重要内容变化后必须重新确认。
- 测试和校准默认停在最终发布按钮之前。
- 点击发布后无法确认结果时标记为“待核实”，并锁定重复发布。
- 只有手机端确认已经发布后，才能在网页点击“确认手机已发布”。

## 十三、建议开发顺序

### 阶段 A：素材和草稿

1. 图片文件夹、产品、场景和标签数据模型。
2. 文件夹管理与批量上传。
3. 草稿工坊按分类选图。
4. 草稿拖拽排序、封面和保存状态。
5. 发布全链路顺序验证。

### 阶段 B：指令复用

1. 指令中心接入草稿工坊。
2. 指令中心接入图片工坊。
3. 指令组合预览、版本、收藏、最近使用和默认值。

### 阶段 C：设备助手

1. 账号矩阵加入电脑节点和连接方式。
2. 设备助手协议、心跳和任务队列。
3. macOS 设备助手。
4. Windows 设备助手。
5. USB与无线动态发现、切换和重连。

### 阶段 D：企业交付

1. 多租户和角色权限。
2. 企业服务端安装包。
3. 中央授权、健康监控和脱敏日志。
4. 签名更新、备份、迁移和回滚。
5. 官方模板与客户模板分层。

## 十四、核心验收标准

- 不同公司无法访问对方任何业务数据。
- 中央平台不保存客户正文、图片、Cookie和API Key。
- Mac和Windows设备助手可同时在线。
- USB和无线ADB均可绑定、检查、校准和发布。
- 无线地址变化不需要修改源代码。
- 多手机不会路由到错误设备。
- 图片可按文件夹、产品和场景管理。
- 草稿、发布中心和手机的图片数量及顺序完全一致。
- 挂车商品能从本地商品库筛选，并在手机精确勾选。
- 图片数量、顺序或商品校验失败时必须中止。
- 升级不会覆盖客户数据和客户模板。
- 更新包经过签名验证，升级前自动备份，失败可回滚。

## 十五、交给后续 Codex 窗口的执行要求

1. 先完整阅读本文档，不要一次性实施全部架构。
2. 先检查当前代码、数据模型、迁移、路由和页面。
3. 每次只实施一个明确阶段，并先说明修改边界和验收方案。
4. 不得在未备份前执行破坏性数据迁移。
5. 不得为测试而触发小红书最终发布。
6. 账号、手机、挂车和最终发布必须保留人工审核门。
7. 优先从阶段 A 开始，不要先做大规模安装包和中央控制平台。

## 十六、仍需确认的产品决策

- 客户服务端默认是否只允许局域网访问。
- 是否支持客户跨地点、跨网络办公。
- 计费方式：公司、席位、手机数、模块或年费。
- 客户是否可以关闭中央健康监控。
- 商品库由客户手工维护，还是从手机小红书商品页同步。
- 首批外部图片同步来源：Obsidian、NAS、本地文件夹、网盘或其他系统。
- 企业服务端优先支持 macOS、Windows 还是 Docker/Linux。
