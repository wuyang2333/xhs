# 阶段 C：设备助手

> **状态：未开始**（2026-08-05 讨论定型）
> 上游：[00-总纲.md](00-总纲.md) 第五节 + 第十三节阶段 C
> 相关决策：[DECISIONS.md](../DECISIONS.md) 2026-08-05 设备助手条

## 要解决什么

需要连手机的电脑上装一个助手程序，负责操控手机发笔记。普通编辑只开浏览器，不装这个。

平台：**Windows + Mac 都做**。Windows 是最终设备形态，Mac 是用户当前使用的一体机。

连接方式：**只做 USB，不做无线**。两台目标机器 USB 都可用。

同事的 Mac mini 排除在范围外——它是唯一逼出无线需求的机器（USB 授权弹窗多种手段均无法唤出），用户明确不再处理。

## 身份与通道

| 信息 | 性质 | 怎么处理 |
|---|---|---|
| 手机序列号 | 身份 | 绑定时记下，长期有效 |
| adb 路径 | 环境 | 助手自己找，不写死 |

USB 下 adb 返回的设备地址**就是手机硬件序列号**，所以身份识别天然可靠，不用额外处理。

## 已经做对的部分（不用改）

`android_xhs_service.py` 里每个 adb 调用都带 `-s <目标>` 明确指定设备，不是「默认操作第一台」。加上 USB 下地址即序列号，总纲第十四节「多手机不会路由到错误设备」**已经成立**。

## 如果将来要恢复无线

无线下地址变成 `IP:5555`，而 IP 会随手机重连 wifi、路由器重启而变化。届时必须先补：

1. 绑定时记录硬件序列号（`ro.serialno`），不记 IP
2. IP 和端口只作为「此刻如何找到它」的临时信息
3. **每次操作前核对序列号，对不上立即中止**

另外无线调试对整个局域网开放，无需认证即可操作手机——这个安全问题也要一起解决。

（说明：同一 wifi 内多台手机不会有相同 IP，那会冲突。之前看到的相同部分是端口 `5555`，那是无线调试的固定端口，所有设备一致。）

## 助手要做的事

- 自己找到并管理 adb，不要求用户配路径
- 报告当前能看到哪些手机、各自序列号、连接方式、状态
- 开机自启、定期心跳、上报版本
- 接服务端下发的任务：传图、选图、填文案、挂车、截图、回传结果
- 每个操作明确指定目标手机

## 账号矩阵要显示

哪台电脑、什么系统、手机型号、**序列号**、在线状态、最近心跳、校准状态、当前任务。

操作按钮：重新配对、检测、校准。

## 手机独占

一台手机连在哪台电脑上就由哪台使用。USB 物理独占，线只能插一台电脑，**不需要软件锁**。

## 未定的事（不阻塞开工，但对外交付前必须解决）

- 服务端与助手之间如何互认：配对密钥怎么下发和轮换、任务是否签名、助手怎么确认任务来自本公司服务端
- ADB 授权私钥的本地保护方式
- 图片张数校验的具体机制（见 [DECISIONS.md](../DECISIONS.md) 待议区）
- 手机适配规则的格式（小红书版本 → 选择器集合）

## 开工前要先修的

`android_xhs_service.py` 依赖的 `xhs_android.py` 只存在于 `~/.codex/skills/xhs-publishing-workflow/scripts/`，**不在仓库里**（BUG-03）。换电脑或对外交付时这个功能会静默失效，不报错。

做 Windows 版之前必须先把脚本搬进仓库，否则 Windows 机器上根本没有它。

## 连机自检：发布前必须把所有手机相关按钮走通

**这是硬性要求，不是建议。** 每次在新机器上连手机后、以及每次改动手机相关代码后，都要按下面顺序把按钮点一遍，**走到「发布前」为止**。

理由：手机侧的失败几乎全是运行时才暴露的——UI 层级变了、相册在屏幕外、输入法没装、授权掉了。这些在开发机上一个都测不出来，而一旦漏到真实发布，发出去撤不回来。

### 自检清单（按此顺序）

| # | 动作 | 期望 | 失败说明什么 |
|---|---|---|---|
| 1 | 一键安装 adb | 下载解压成功，状态变「已就绪」 | 网络问题 / 平台包地址失效 |
| 2 | 检测设备 | 列出手机，状态 `device` | `unauthorized` = 手机上没点允许；空列表 = 线或 USB 调试没开 |
| 3 | 安装中文输入法 | 装好且已启用 | 装不上则后面填不了中文 |
| 4 | 设备体检（doctor） | 报出机型、安卓版本、小红书版本、当前输入法 | 小红书未安装 / 版本过老 |
| 5 | 校准（calibrate） | 能进到相册并找到可选图片 | **相册在屏幕外时容易假失败**，见下 |
| 6 | 传图（push） | 图片进入手机 `Pictures/CodexXHS` | 路径权限问题 |
| 7 | 打开发布页（open） | 停在图片选择界面 | 小红书 UI 改版 |
| 8 | 选图并核对数量 | 手机实际选中数 == 任务图片数 | 数量不一致必须中止，不得只带部分图继续 |
| 9 | 填写标题正文（fill） | 中文正确填入，无乱码无截断 | 输入法未生效 |
| 10 | 挂车（若本次需要） | 精确匹配到商品并勾选 | 找不到 / 有歧义必须中止，不得静默发普通笔记 |
| 11 | 截图核对（screenshot） | 能看到最终待发布状态 | —— |
| **停** | **到此为止，不点最终发布** | —— | 测试绝不触发真实发布（见 [CLAUDE.md 红线](../../CLAUDE.md#红线不可逆操作)） |

第 5 步要特别注意：2026-08-06 实测遇到过「相册明明在下面、脚本却报找不到」——原因是 uiautomator 只导出已渲染的行，屏幕外的相册不在 UI 树里。已加 `scroll_to_find_node` 滚动查找并配 5 个测试。**同类问题可能出现在任何需要在长列表里找东西的地方**（挂车选商品、选账号），遇到「明明看得见却说找不到」先怀疑这个。

### 这份清单要落成界面

建议在账号矩阵或任务中心加一个「连机自检」面板，把 1–11 步做成可逐项点击、逐项显示结果的列表，最后一步明确标注「测试到此结束，不会发布」。

这样换机器部署时不用记流程，照着点完即可；也避免了「以为都好了，结果发布时才炸」。
