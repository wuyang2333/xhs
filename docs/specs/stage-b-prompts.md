# 阶段 B：指令中心复用

> **状态：未开始，后端缺两层字段**（2026-08-05 讨论定型）
> 上游：[00-总纲.md](00-总纲.md) 第八节 + 第十三节阶段 B

## 要解决什么

指令中心现在能存指令、记版本，但只是个档案柜。要让它变成草稿工坊和图片工坊里的**指令选择器**——写文案时选一条改写指令，生图/改图时选一条图片指令。

## 现状

已有：`prompt_templates`（含 `source_type` / `source_ref` / `source_hash`）、`prompt_versions`、`prompt_usages`，可绑定到 `platform_account_id`。

**实际做法：单选直用，不做分层叠加。**

总纲第八节原本设想六层组合，但用户明确要求「直接选一条指令就按它执行，而不是叠加」，B-03 已推翻重做。产品 / 场景字段仍然有用——它们用于**筛选**指令（找到「坐浴盆专属」那条），而不是拼接。

选中一条后，它的正文即最终指令，会整体取代后端默认人设。用户也可以不选、直接自己填。

需要给指令表加 `product_id` 和 `scene_id`（都可空），复用阶段 A 已建好的 `products` 和 `asset_scenes` 表。

## 另一个缺口：官方模板与客户模板分不开

总纲第八节要求「官方模板由我方更新；客户模板永不被升级覆盖」，第十一节同样要求升级不得覆盖客户自建指令。

现有 `source_type` 默认 `"manual"`，**没有显式的官方标记位**，升级流程无从判断哪条可以覆盖。

建议加 `is_official` 布尔位，并规定：客户复制官方模板后，副本的 `is_official` 置为 false——这同时落实总纲第八节「复制后修改不影响原指令」。

## 要做的

1. 后端加 `product_id`、`scene_id`、`is_official` 字段
2. 草稿工坊接入选择器：生文、改写、标题、正文、标签、合规检查指令
3. 图片工坊接入选择器：生图、图片分析、白底图、卖点图、使用场景、风格、产品一致性指令
4. 执行前展示**最终合并后的完整指令**（总纲第八节明确要求）
5. 收藏、最近使用、默认指令、组合模板
6. 草稿记录实际使用的指令 ID 和版本

## 验收

- [ ] 可按产品、场景创建和筛选指令
- [ ] 草稿工坊和图片工坊都能选指令
- [ ] 执行前能看到合并后的完整指令
- [ ] 复制官方模板后修改，不影响原指令
- [ ] 升级不覆盖 `is_official = false` 的模板
- [ ] 草稿里能查到用过哪条指令的哪个版本
