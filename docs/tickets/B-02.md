## 目标

让指令中心从「档案柜」变成「选择器」。用户在草稿工坊写文案、在图片工坊生图时，能直接选一条已沉淀的指令，而不是每次手打。

这是用户最早提的需求原话：「指令中心是能沉淀指令库了，但是怎么复用到生文的草稿工坊中选择指令和图片工坊中选择指令」。

## 核心：分层组合

总纲第八节要求的组合方式：

```
基础指令 + 平台指令 + 账号指令 + 产品指令 + 场景指令 + 本次临时补充 = 最终执行指令
```

**执行前必须展示合并后的完整指令**，这是总纲明确要求的——用户要能看到真正发给模型的是什么，而不是盲盒。

组合规则：

- 各层都可为空，空层直接跳过
- 层间用换行分隔
- 顺序固定为上面的顺序（基础在最前，临时补充在最后）
- 合并结果要能在执行前编辑（编辑后不回写原指令，属「本次临时」）

### 已知副作用与偏差（三项，都是后端不可改导致的）

1. **标题指令走 `body` 夹带。** `/ai/generate-title` 的 `GenerateTitleRequest` 只有
   `title` / `body` / `count`，**没有 `instruction` 字段**，本单又不许改后端。
   所以标题指令以 `\n\n【写作要求】\n…` 追加在 `body` 末尾送达，并按 6000 上限裁正文尾部。
   要做干净，需后端给 `/ai/generate-title` 加 `instruction`（下一单可做，S 档）。
2. **标签生成未接选择器。** 后端 `prompt_type` 枚举是
   `^(image|note|title|rewrite|auto_ops)$`，没有 tags 类型，无从选起；
   本单验收清单也未要求标签。`generateTagOptions` 保持原样。
3. **基础层与平台层共用「未绑定指令」候选池。** 后端没有显式的「层」字段，
   产品 / 场景 / 账号三层由绑定关系推出，未绑定的同时出现在基础层与平台层下拉里，
   由用户决定放哪个槽位。若要严格区分，需后端加一个 `layer` 字段。

另外：`is_official` 不在后端 `PromptPayload` 里（由「改正文自动置 false」的服务端逻辑维护），
所以指令中心只把它当只读标记展示，不提供手工勾选。
