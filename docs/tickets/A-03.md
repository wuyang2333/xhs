# A-03：上传时自动建文件夹

> 状态：**已完成**（2026-08-06）
> 规格：[stage-a-assets.md](../specs/stage-a-assets.md)

> 执行：主会话直接做

## 目标

上传素材时，文件夹不存在就自动建出来。原先必须先手动建好文件夹才能传。

## 设计

用**路径**表达层级，而不是要求前端先查再建：

```json
{ "asset_type": "image", "url": "...", "folder_path": "坐浴盆/卫生间场景" }
```

缺失的层级逐级创建；已存在的直接复用，不会产生重名副本。这与用户的分类习惯（产品 + 场景）和总纲第六节的示例（`坐浴盆 / 白底产品图`）直接对应。

`folder_id` 与 `folder_path` 同时传时 **`folder_id` 优先**——显式指定的意图强于路径推断。

## 改动

- `backend/app/services/media_asset_service.py` 新增 `resolve_folder_path()`。放在服务层而非 API 层，顺带缓解 BUG-04 记录的分层问题（此前该文件只有 1 个函数）。
- `backend/app/api/assets.py`：`AssetCreateRequest` 增 `folder_path` 字段；`create_asset` 在 `folder_id` 为空且 `folder_path` 非空时解析路径。`ValueError` 转 400。
- `frontend/src/lib/api.ts`：`createMediaAsset` 参数增 `folder_path`。

## 边界与约束

- 层级上限 8 层，超出返回 400 且不留下任何半成品文件夹
- 单段名称上限 128 字符（与 `asset_folders.name` 列长度一致）
- 分隔符兼容 `/` 与 `\`，空段自动忽略（`坐浴盆//场景` 等价于 `坐浴盆/场景`）
- 同名匹配区分大小写，与数据库既有唯一约束 `(user_id, parent_id, name)` 行为一致
- 跨用户隔离：不同用户的同名路径互不影响
