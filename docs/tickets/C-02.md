## 要解决什么

用户即将把系统部署到 Windows。**部署之后没有人替他敲命令行**——没有 Codex、没有 Claude、没有终端操作。

所以「设备助手自动完成」必须字面成立：从零到能发布，全部在网页上点完。

用户的原话划定了边界：

> 手动打开开发者选项这些事肯定要的，但是做到连接手机，打开 usb 调试做完就要能自动连接

即：**手机上开开发者选项 + USB 调试 + 授权弹窗，这三步用户手动做**（安卓安全设计，程序无法代替）。除此之外的一切都必须自动。

## 现状：三个硬缺口

**一、adb 只检测不安装。**

`android_xhs_service.setup_status()` 只返回 `adb_available: bool`。没装就返回 false，前端提示「未安装 ADB：先完成一次性安装」——而那份文档要求用户跑 `brew install` 或手动执行 `setup_android.py`。Windows 上用户根本无从下手。

仓库里已有 `scripts/android/scripts/setup_android.py`，能从谷歌官网下载三个平台的 platform-tools（Darwin / Linux / Windows 地址都在）。**缺的是把它接成一个接口 + 一个按钮。**

**二、Windows 上找不到 adb（即使装好了）。**

`_adb_path()` 的候选路径写的是 `.../platform-tools/adb`，但 **Windows 上可执行文件叫 `adb.exe`**。`shutil.which("adb")` 在 Windows 上能靠 PATHEXT 兼容，但那个显式拼出来的本地路径不行。

**三、中文输入法要装到手机上，但没有接口。**

`xhs_android.py` 有 `install-ime` 子命令，装仓库内的 `assets/ADBKeyboard.apk`（adb 原生输入命令打不了中文，填标题正文必须靠它）。脚本里还处理了小米 HyperOS「装完默认禁用」的情况。**但服务层没有对应方法，接口层也没暴露。**

## 要做的

### 1. 后端：三个新接口

- `POST /api/accounts/android/setup-adb` —— 调用 `setup_android.py` 的逻辑下载安装 platform-tools。要点：
  - **必须能报告进度或至少是长任务**（下载几十 MB，同步阻塞会超时）。建议走项目已有的 `task_service` / `task_runner` 模式，返回任务 id 供前端轮询
  - 已安装时直接返回成功，不重复下载（幂等）
  - 下载失败要给出可读原因（无网络 / 被墙 / 磁盘满），不要抛原始异常
- `POST /api/accounts/android/install-ime` —— 参数 `serial`，装 ADBKeyboard 到指定手机
- 扩展 `GET /api/accounts/android/setup-status` —— 增加 `ime_installed`（该手机是否已装输入法）等字段，让前端能画出完整清单

### 2. 后端：修 Windows 路径

`_adb_path()` 的候选要按平台加 `.exe`。建议同时检查 `adb` 和 `adb.exe`，不要用 `sys.platform` 硬分支——这样 macOS 上的行为完全不变，Windows 上多一条候选即可。

`setup_android.py` 解压后的可执行文件名也要按平台确认。

### 3. 前端：连接向导

`frontend/src/components/account/android-bind-panel.tsx` 改成分步向导，每步显示状态并给出可点的动作：

| 步骤 | 谁做 | 界面上要有 |
|---|---|---|
| 1. 安装 adb | 程序 | 「一键安装」按钮 + 进度 + 失败原因 |
| 2. 手机开发者选项 + USB 调试 | **用户手动** | 图文说明，讲清在哪点 |
| 3. 插线并授权弹窗 | **用户手动** | 说明「必须解锁手机」「USB 用途选文件传输」「勾选始终允许」 |
| 4. 检测设备 | 程序 | 「检测」按钮，区分 `unauthorized` / `device` 两种状态并给不同提示 |
| 5. 安装中文输入法 | 程序 | 「一键安装」按钮，说明用途（不装就打不了中文） |
| 6. 绑定账号 | 用户选择 | 现有绑定流程 |

第 4 步的 `unauthorized` 状态要明确告诉用户「回手机点允许」，而不是只显示状态码。同事那台 Mac mini 卡住的正是这一步。

### 4. 文档

`docs/同事Mac安卓USB绑定.md` 现在写的是手动命令行流程，与新的网页向导冲突。改成指向网页向导，只保留手机侧那几步手动操作说明。

## 进度记录

### 2026-08-05 执行完成（静态验证，未经真机）

**门禁**：`npx tsc --noEmit` 退出码 0；`pytest tests -q` **200 passed**（基线 174，新增 26 个阶段 C 测试）。

**改了什么**

`backend/app/services/android_xhs_service.py`

- `_adb_path()` 候选加了 `ADB_EXECUTABLE_NAMES = ("adb", "adb.exe")`，两个名字都试。**没有用 `sys.platform` 硬分支**，macOS 行为不变。安装目录可用 `XHS_ADB_INSTALL_DIR` 覆盖（测试隔离需要）。
- 新增 `AdbInstallTask` + 模块级 `adb_install_registry`。项目原有的 `core/task_runner.py` 只能登记状态、不能执行，`task_service.py` 是 mock 数据，两者都接不了这活，所以按同样的「注册 + 轮询」形态在本服务内实现，后台线程跑下载。
- `start_adb_install()` 幂等：已装 adb 直接返回 success + `already_installed=True` 且不发起任何下载；已有任务在跑就返回同一个 task id。
- `install_adb_sync()` 分段上报进度（5/15/70/90/100）。`_download_platform_tools()` 单独成方法便于 mock——**测试从不访问外网**。
- `_readable_download_error()` 把异常翻成人话：无网络 / HTTP 错误 / 超时 / 磁盘满(errno 28) / 无权限(errno 13) / 包损坏。断言过不泄漏原始 `Errno` 文本。
- 新增 `install_ime(serial)`、`ime_installed(serial)`。装之前先查设备状态，`unauthorized` 时直接给「勾选始终允许」的可操作提示，不调脚本。
- `setup_status(serial=None)` 增加 `platform` / `adb_installable` / `adb_install_task_id` / `ime_installed` / `ime_checked` / `ime_serial`。输入法探测失败只置 `ime_checked=False`，不让状态接口 500。
- `_adb()` 缺 adb 时的报错从「跑 brew / python3 命令」改为指向网页第 1 步的按钮。

`backend/app/api/accounts.py`（仅安卓端点）

- `POST /android/setup-adb`、`GET /android/setup-adb/{task_id}`、`POST /android/install-ime`；`GET /android/setup-status` 加可选 `serial` 查询参数。

前端

- `android-bind-panel.tsx` 重写为 6 步向导。**扁平竖排，无 Collapse、无二级弹窗**，每个按钮直接可见。第 2、3 步打橙色 `需你手动操作` 标签，其余打 `系统自动完成`。顶部横幅一句话点明「只有第 2、3 步要你动手」。
- 第 4 步区分 `unauthorized`（大段可操作指引：解锁手机、找弹窗、勾选一直允许、USB 改文件传输）与 `device`（绿色已就绪）。
- 第 1 步含 `Progress` 进度条 + 失败原因 Alert + 「重试安装 ADB」。任务未终态时 1.5s 轮询。
- 配色全走 `theme.useToken()`。此处踩过一次：面板挂在 `add-account-drawer.tsx` 的深色 Drawer 里，原先写死的 `#fff` 背景和 `rgba(0,0,0,0.65)` 文字在深色主题下不可读。
- `types/index.ts` 加 `AdbInstallTask`、`AndroidImeInstallResult`，扩 `AndroidSetupStatus`；`api.ts` 加三个函数。无 `any`，无未使用 import。

`docs/同事Mac安卓USB绑定.md` 重写为指向网页向导 + 只保留手机侧手动步骤。`docs/STATE.md` 已更新基线与未验证声明。

**顺手修掉的隐患**：任务若卡在 `pending`（线程被杀 / 进程假死），安装按钮会永久点不动——而部署后用户没有命令行兜底。加了 `STALE_SECONDS = 600` 的超时判定，过期任务标记失败并放行重试。

**已知副作用 / 取舍**

1. **platform-tools 下载地址在两处**：`setup_android.py` 与服务的 `PLATFORM_TOOLS_URLS`。没有改成 subprocess 调那个脚本，因为它 `print` + `raise SystemExit`，拿不到进度也拿不到结构化错误。用 `test_service_urls_match_vendored_setup_script` 锁住两边一致，改一边会红。
2. 任务表在进程内存里，**后端重启后进行中的安装任务丢失**。重启后重新点即可（已装的话会走幂等分支）。
3. 下载进度是**分段的，不是字节级百分比**。`urlretrieve` 没接 reporthook，进度条会在 15% 停一会儿。
4. `XHS_ADB_INSTALL_DIR` 是本单新增的环境变量，已写进文档。
5. 未动 `xhs_android.py`、`apis/`、`xhs_utils/`、`publish.py`、迁移。未触发任何发布。

**哪些没能验证（不要当成已验证）**

真机部分全部未验：一键装 adb 是否真能下载解压成功（下载全程 mock）、Windows 上 `adb.exe` 是否真被找到（用文件布局模拟，没上过 Windows）、`unauthorized → device` 状态流转、装完输入法中文能否真的填进小红书、向导在浏览器里的实际观感。**需要真机 + Windows 各跑一遍。**
