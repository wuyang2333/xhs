## 目标

草稿工坊底部能直接从素材库选图，选完能拖拽排序、设封面。依据总纲第七节。

**这一单的核心不是界面好看，是顺序不能错。** 图片顺序的唯一权威来源是草稿的 `sort_order`，发布中心按它复制，手机按它编号。顺序错了会发出错图。

## 要做的

**选图器**（草稿工坊底部）
- 从素材库选图，按产品 / 场景 / 文件夹 / 标签筛选
- 支持「最近上传」「最近使用」
- 一键全选当前文件夹
- **防重复**：已在草稿里的素材不能再选。后端 `(draft_id, media_asset_id)` 有唯一约束，重复加会报错，界面要提前禁用而不是让用户撞到错误
- 加入草稿走 `addDraftAsset(draftId, { media_asset_id })`

**已选素材区**
- 显示序号（1、2、3…），这是用户核对顺序的主要依据
- 拖拽排序 → `reorderDraftAssets(draftId, assetIds)`
- 设为封面 → `setDraftAssetCover(draftId, assetId)`；后端保证每草稿恰好一个封面，界面要反映这个唯一性
- 删除 → `deleteDraftAsset`
- 替换 → `updateDraftAsset`

**保存状态**
- 顺序改动后显示「保存中 / 已保存」
- **送发布中心前必须等待顺序保存完成**——这是总纲第七节的硬要求。保存未完成时「送发布」按钮要禁用，不能让用户在顺序还没落库时就发出去

**修掉一个既有 bug（本单核心风险点）**

原 `handleDragEnd` 只把**图片** id 提交给 `reorderDraftAssets`，而后端要求该草稿的**完整**素材集合，含视频的草稿必然 400；且当时是 `.catch(console.error)` 静默失败，界面显示新顺序而库里仍是旧顺序——正是「发出错图」的路径。

现改为 `persistImageOrder()`：拖拽后的图片顺序 + 未参与拖拽的视频按原相对顺序拼成完整集合再提交，并把失败暴露成 `error` 状态挡住送发布。

**顺序落库状态**

`orderStatus: idle | saving | saved | error`，用 `inFlightReorders` ref 记在途请求数，全部 resolve 才转 `saved`。`saving` 与 `error` 两态都禁用「送入发布中心」按钮，`handleSendToPublish` 里另有一道 guard。换草稿时重置状态，避免上一篇的状态误挡/误放当前篇。保存中禁止再拖，规避并发 reorder 竞态。

**防重复做在界面层**

后端 `POST /drafts/{id}/assets` 除 `media_asset_id` 外还按 `url` / `local_path` 判重返 409，所以选图器三者都纳入禁用判断（置灰 + 「已加入」角标 + checkbox disabled），不让用户撞后端错误。批量加入仍对 409 单独兜底计数提示。

**其他**

- 选图器：文件夹（TreeSelect 嵌套）/ 产品 / 场景 / 标签 / 搜索 筛选，最近上传、最近使用排序，一键全选当前文件夹 + 全选当前结果 + 清空
- 加入草稿按用户勾选先后**串行**提交，序号与预期一致（并行会乱序）
- 设封面走 `setDraftAssetCover`，本地状态同步把其他项 `is_cover` 置 false，界面恒只有一个封面
