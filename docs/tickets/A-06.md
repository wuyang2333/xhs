## 问题

系统里并存三套互不相通的图片存储：

| 存储 | 现有数量 | 谁在读 |
|---|---|---|
| `media_assets`（A-04 建的素材库） | 3 | A-05 的草稿选图器 |
| `ai_generated_assets` | 33 | 图片工坊「AI 生成图片」列表 |
| 磁盘 `backend/app/storage/media/` | 279 文件 | 「上传图片」列表（`GET /api/files/images` 直接扫目录，**无数据库记录**） |

后果：

1. **草稿工坊选图器几乎是空的**——它只读 `media_assets`，而用户的 201 张上传图和 20 张 AI 图在另两套里
2. **AI 生成的图进不了素材库**，无法归类、无法按产品/场景筛选
3. **发布中心和草稿工坊的「从图片工坊添加」弹窗仍是旧 UI**（Tabs 分「AI 生成图片 / 上传图片」），**不能选文件夹**

总纲第六节把素材库定为统一入口，但既有资产从未迁入，AI 生图链路也没往里写。

## 要做的三件

### 一、AI 生图同时落素材库

`backend/app/api/ai.py` 里创建 `AiGeneratedAsset` 的地方（至少两处：约 353 行 `generate_note` 路径、约 532 行单图生成路径），同时调用 `register_media_asset(..., source="ai")` 写入 `media_assets`。

- 保留 `ai_generated_assets` 表和现有列表功能，不要删——它承载 prompt、model_name、params 等生成元数据，`media_assets` 没有这些字段
- 两者通过 `file_path` / `url` 关联即可，不必加外键
- `source` 字段用 `"ai"` 以便前端区分来源

### 二、一次性回填已有资产

写一个脚本放 `scripts/backfill_media_assets.py`，把已有资产补进 `media_assets`：

- 33 条 `ai_generated_assets` → `source="ai"`
- 磁盘 `storage/media/` 下符合 `xhs-upload-u{user_id}-` 前缀的图片文件 → `source="upload"`，`user_id` 从文件名解析

要求：

- **幂等**：重复运行不产生重复记录。`register_media_asset` 已按 `local_path` / `url` 去重，复用它
- **不删除任何原有数据**
- 打印统计：扫描多少、新增多少、跳过多少
- 支持 `--dry-run` 先看结果不落库
- 回填的素材 `folder_id` 留空（未归类），用户自己整理

**执行前必须备份**，见 `CLAUDE.md` 红线。

### 三、替换旧的「从图片工坊添加」弹窗

两处入口都要换成支持文件夹的选图器：

- **发布中心**：`frontend/src/pages/platforms/xhs/publish-page.tsx`，「从图片工坊添加」按钮
- **草稿工坊**：`frontend/src/pages/platforms/xhs/rewrite-page.tsx`，「上传 / 链接添加」旁边如果还有旧入口一并处理

新弹窗要有：文件夹树或文件夹筛选、按产品 / 场景 / 标签筛选、搜索、来源筛选（全部 / AI / 上传）。

**A-05 已经做好了 `frontend/src/components/drafts/draft-asset-picker.tsx`**，优先复用或抽成通用组件，不要再写第三套选图逻辑。

### 2026-08-06 执行完成

三件事全部做完，两个门禁都过：`tsc --noEmit` 退出码 0，`pytest tests -q` **158 passed**（基线 151，新增 7）。

**一、AI 生图落素材库**（`backend/app/api/ai.py`）

新增 `_register_ai_media_asset()` 辅助函数，**三处**创建 `AiGeneratedAsset` 的地方都接上了（单子说「至少两处」，实际是三处）：

| 行 | 路径 | 条件 |
|---|---|---|
| ~353 | `generate_note` 批量配图 | 每张图都登记 |
| ~532 | `generate_cover` 单图 | 无条件 |
| ~571 | `generate_image` | **仅 `save_to_assets=True`**，与 `AiGeneratedAsset` 落库条件一致 |

两个实现细节值得记一笔：

- **用 `db.begin_nested()`（SAVEPOINT）包住登记**。素材库登记失败不能连累主流程——图已经生成并落盘了。但直接 `except: db.rollback()` 会把同事务里已 `add` 的 `AiGeneratedAsset` / `AiDraft` / `DraftAsset` 一起丢掉，比少一条素材库索引更糟。SAVEPOINT 只回滚登记这一步。
- `original_name` 截断到 120 字符。该列限长 256，而 prompt 可以上千字（现有数据里就有）。

`ai_generated_assets` 表和列表接口一行未动，prompt / model_name / params 元数据仍在原处。

**二、回填脚本**（`scripts/backfill_media_assets.py`，新建）

幂等性直接复用 `register_media_asset()` 的 `local_path` / `url` 判重，没有自己写去重。`--dry-run` 另有一个 `_asset_exists()` 用同一口径预测结果。

实际执行结果（备份 `20260806-113949-464197-pre_a06_media_asset_backfill` 已确认存在后才跑）：

```
AI 资产：扫描 33，新增 33，已存在跳过 0，无效跳过 0
磁盘上传图：扫描 201，新增 198，已存在跳过 3，无效跳过 0
合计新增：231
回填后 media_assets：234 条（回填前 3）
```

第二次运行：`合计新增：0`，总数仍 234。库内核对：`source` 分布 `ai=33 / upload=201`，无重复 `(user_id, local_path)`，231 条 `folder_id` 为空（未归类），`ai_generated_assets` 仍 33 条。

两个判断需要留意：

- **AI 资产同时写 `url` 和 `local_path`**。`ai_generated_assets.file_path` 存的是 URL（`/api/files/media/xxx.png`），从中解析出裸文件名一并写入，这样后续 AI 生图再走 `register_media_asset` 时 `local_path` 判重才对得上，不会撞出重复行。
- **磁盘侧只扫 `xhs-upload-u{id}-` 前缀**，按单子要求。目录里另有 80 个 `xhs-image-u1-*`（AI 生图落盘文件），其中 33 个已由来源一覆盖，剩下 47 个是历史上生成但从未写进 `ai_generated_assets` 的孤儿文件——**没有回填**，见下方已知副作用。
- `original_name` 用磁盘文件名兜底。上传时原始文件名被 uuid 重命名且磁盘无留存，已不可考。

单子写「磁盘 279 个上传文件」，实际目录里 281 个文件 = 201 upload + 80 image，符合前缀的是 201 个。

### 已知副作用

1. **磁盘上的 `xhs-image-u1-*` 孤儿文件未进素材库。** AI 落盘文件里只有 33 个在 `ai_generated_assets` 有记录，其余是早期生成但元数据未落库的，除 user 归属外没有任何信息。单子把磁盘回填限定在 `xhs-upload-` 前缀，所以按单子做了。若要收进来，扩一条 `xhs-image-u{id}-` 前缀规则即可（`source="ai"`，prompt 缺失）。**一个文件都没删。** 已记为 `STATE.md` BUG-06。

   收尾核对时发现这批文件数量在**随测试轮次增长**：`tests/backend/test_api.py` 里两个测试用真实 `data:image/` 载荷走 `_persist_base64_image`，而测试没覆盖 `storage_dir`，每跑一次全量测试就往真实媒体目录漏 2 个文件（本会话在首次计数后又跑了三轮，`xhs-image-u1-*` 80→86）。**非本单引入**，基线那轮就在漏，按「做 A 单时发现 B 的 bug 不停下来修」的纪律未修，已记为 BUG-09。
2. **回填的 231 条素材全部未归类**（`folder_id` 为空），按单子要求。用户在图片工坊里会看到一大批散图待整理。
3. **`GET /api/files/images` 仍然存在**，仍在被 rewrite-page 的参考图选择器使用，未删。现在它和素材库对同一批磁盘文件有两套读法，数据一致但入口重复——属于后续可收敛项，不在本单范围。
4. **前端未经浏览器验证。** 与 A-04 / A-05 同样的情况：过了 `tsc --noEmit` 与 `vite build`，但页面在登录保护之后，交互按后端行为编写。建议实际点一遍：发布中心「从图片工坊添加」的文件夹筛选与来源筛选、草稿工坊选图器能否看到回填进来的 231 张图。
5. `scripts/backfill_media_assets.py` 需要仓库根在 `sys.path` 上，已在文件内自行 bootstrap，从任意目录执行都可以。
