## 目标

把图片工坊的主流程从「API 生图」改成「上传 + 分类管理」。API 生图降级为辅助功能保留，不删除。

依据总纲第六节：主流程为批量上传、分类管理、草稿选图和排序。

## 现状

`frontend/src/pages/platforms/xhs/image-studio-page.tsx`（816 行）当前是围绕 AI 生图组织的，用 `Tabs` 分区，已有：AI 生图、图片描述、参考图选择、生成资产管理、用户图片列表。

**素材域（文件夹/产品/场景/标签/素材）在这个页面里完全没有体现**，但后端 21 个接口和前端 22 个客户端函数都已就绪。

## 要做的

新增一个「素材库」区域作为页面主入口（建议放在 Tabs 第一位，把现有 AI 生图移到后面），包含：

**文件夹树**
- 展示嵌套结构（`parent_id` 自引用）
- 新建、重命名、移动（改 `parent_id`）、删除
- 删除非空文件夹时后端返回 409，要给出明确提示（「文件夹非空，请先移出其中内容」）
- 设置文件夹封面（`cover_asset_id`）；注意后端要求封面素材必须属于该文件夹，否则 400

**批量上传**
- 支持多选文件
- 可指定目标文件夹，也可直接填路径（如 `坐浴盆/卫生间场景`）自动建层级
- 两步链路：先 `uploadAssetFile(file)` 得到 `UploadedFile`，再 `createMediaAsset({ asset_type, url: download_url, local_path: file_name, original_name, file_size, source: "upload", folder_path 或 folder_id })`
- 要有上传进度与失败计数（现有页面已有 `uploadingCount` / `uploadFailedCount` 模式可参考）

**素材网格**
- 缩略图展示，支持多选
- 批量移动到文件夹、批量改产品/场景/标签（`batchUpdateMediaAssets`）
- 拖拽排序（`reorderMediaAssets`）
- 删除（`deleteMediaAsset`）

**筛选与检索**
- 按文件夹、产品、场景、标签筛选
- 关键词搜索（后端匹配 `original_name` / `url` / `local_path`）
- 「最近」开关（`recent=true`，后端返回 30 天内创建或使用过的）
- 分页（`page` / `page_size`，上限 100）

**产品 / 场景 / 标签管理**
- 各自的增删改查入口，可以放在抽屉或弹窗里，不必占主界面
- 标签有颜色字段

**改动的既有文件**：

- `image-studio-page.tsx`：Tabs 第一位换成「素材库」（`AssetLibraryPanel`），原来平铺在页顶的 AI 生图 + 图片描述两张卡抽成 `aiToolsRow` 常量，移到第二个 Tab「AI 生图 / 图片描述」。**AI 生图、图片描述、参考图选择器、AI 资产管理、普通图片资产全部逻辑未删未改，只是换了位置。** 顺带删掉一个从来没被用过的 `InboxOutlined` import。
- `api.ts`：两处修正。① `batchUpdateMediaAssets` 返回类型原本写的是 `{ items: MediaAsset[] }`，后端实际返回 `{"updated_count": N}`——是类型谎报，按 `updated_count` 改正了。② 给 `createAssetFolder` / `updateAssetFolder` / `deleteAssetFolder` / `reorderMediaAssets` / `deleteMediaAsset` 加可选 `silent` 参数（沿用文件里已有的 `_silent as never` 写法，默认 false 不影响任何现有调用），这样 409/400 能出中文提示，而不是全局拦截器直接把后端英文 detail 弹出来。

**踩到的两个点**：

1. **`PUT /assets/reorder` 要的是该用户全部素材的完整集合**，少一个就 400。但界面上拖拽只发生在「当前筛选 + 当前分页」的子集里。解法是槽位投影：拖拽前记下可见 id 在全量顺序中占据的下标，只把这些下标上的 id 换成拖后的顺序，没参与的素材位置分毫不动。函数是 `projectReorderOntoGlobal`，前置条件不满足时返回 `null`，调用方放弃提交并重新拉取。这段逻辑用 8 个用例（含筛选态、分页态、脏数据）单独验过。
2. **antd 6 的 `Checkbox` 不转发 `onPointerDown`**，直接传会 TS2322。外面包一层 `<span>` 拦指针事件，否则拖拽 sensor 会吃掉勾选框的点击。

**已知副作用 / 遗留**：

- **新上传素材的 `sort_order` 默认是 0**（后端 `MediaAsset` 模型的默认值，本单没动后端）。所以做过一次拖拽排序后再上传，新素材会排在最前面而不是末尾——列表实际按 `(sort_order, id)` 排。不影响排序功能本身，但观感上「新图跑到前面去了」。要改得动后端 `register_media_asset`，属另一张单。
- **没做浏览器实机验收**。页面在 `ProtectedRoute` 后面，跑起来要后端 + 登录态，本单只跑到 tsc / vite build / pytest 三道静态与后端门禁。「文件夹能建能删」这类交互项是照 `backend/app/api/assets.py` 的行为写的，逻辑上对齐，但没有人工点过。
- `frontend/dist/` 因为跑 `npm run build` 被重新生成过（该目录已在 `.gitignore` 里）。
- `tsc --noUnusedLocals --noUnusedParameters` 在本单新增/改动的文件上是 0 报错；全项目还有 24 条既有的未使用声明（`router.tsx`、`app-shell.tsx` 等），属本单边界外，没动。
