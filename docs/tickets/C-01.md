## 为什么这是阶段 C 的第一步

设备助手要做 Windows 版，而它依赖的 `xhs_android.py` 原先只存在于开发机的 `~/.codex/skills/xhs-publishing-workflow/scripts/`。Windows 机器上根本没有这个路径，功能会直接哑掉——而且**不报错、不失败构建、不挂测试**，只是不工作。

所以必须先解决自持问题，再谈打包。

## 搬了什么

原目录不只一个脚本，`xhs_android.py` 第 439 行还会读 `../assets/ADBKeyboard.apk`（启用 ADB 输入法用）。所以按原有相对层级搬了三样：

```
scripts/android/
├── scripts/
│   ├── xhs_android.py      # 主脚本，35 KB
│   └── setup_android.py    # 安装 platform-tools
└── assets/
    └── ADBKeyboard.apk     # 17 KB
```

三个文件的 SHA-256 与源文件逐一核对一致。`scripts/` 与 `assets/` 的相对关系必须保持，否则脚本内的 `parent.parent / "assets"` 解析不到。

## 查找顺序改了

`backend/app/services/android_xhs_service.py`：

1. `$XHS_ANDROID_SCRIPT`（显式指定，便于调试改版脚本）
2. **仓库内 `scripts/android/scripts/xhs_android.py`（新增，且优先于外部副本）**
3. `~/.codex/skills/...`（保留，兼容既有开发机）
4. `scripts/xhs_android.py`（保留旧约定）

兜底值也从原来的 `~/.codex` 那份改成仓库内副本——找不到时报的路径应该指向仓库，而不是指向一个别人机器上才有的目录。
